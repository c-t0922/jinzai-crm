## 3. 実装方法（3層チェック）

1. **画面**：`can(user, 'menu.call_lists')` 等でメニュー・ボタン表示を制御。
2. **API**：全 Route Handler / Server Action の先頭で `authorize(user, action, resource)`。権限なしは 403、範囲外リソースは 404。
3. **DB（RLS）**：
   - `contacts`：`is_admin() OR is_pm() OR exists(assignments where user=auth.uid()) OR exists(チームの割当) OR exists(handoffs to auth.uid())`
   - `call_logs`：自分の通話、自チームメンバーの通話（TL）、全件（ADM/PM）。EXE は集計テーブル `kpi_daily` のみ参照可。
   - `audit_logs` / `export_logs`：INSERT のみ（UPDATE/DELETE 禁止、ADM も不可）。
   - ロール判定関数は `security definer` で `user_roles` を参照し、JWT のカスタムクレームにキャッシュ。
4. **テスト**：pgTAP でロール × テーブル × 操作の全組み合わせをテスト（`12_test_plan.md`）。

兼務ユーザーは保持ロールの権限の和集合とする。
