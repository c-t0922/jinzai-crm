# 14. 運用手順（Phase 1 時点）

## 1. バックアップ
- **本番（Supabase Pro 以上）**：日次の自動バックアップ（7 日保持）＋ Point-in-Time Recovery を有効にする。費用は [11_operating_cost.md](11_operating_cost.md)。
- 重要な設定変更・一括処理（利用許諾の一括登録、架電禁止の一括解除など）の前に、管理者が Supabase ダッシュボードから手動バックアップを取得する。
- 論理バックアップ（月 1 回、暗号化して社内の保管場所へ）：
  ```bash
  supabase db dump --db-url "$DB_URL" -f backup_$(date +%Y%m%d).sql          # スキーマ
  supabase db dump --db-url "$DB_URL" --data-only -f data_$(date +%Y%m%d).sql  # データ
  ```
  ファイルには個人情報が含まれるため、パスワード付きで暗号化し、保管場所と閲覧者を限定する。開発 PC・GitHub・チャットには置かない。

## 2. 復元
1. 影響範囲を確認し、利用者に一時停止を連絡する（架電センターを開いている担当者は結果の保存を待つ）。
2. PITR の場合：Supabase ダッシュボード → Database → Backups から復元時刻を指定。
3. 論理バックアップの場合：新しいプロジェクトに復元して内容を確認してから切り替える（本番への直接上書きはしない）。
4. 復元後、`pnpm db:test` 相当の権限テストと、管理者で「架電ルール設定」「利用許諾管理」の値を確認する。
5. 操作ログに復元の記録（日時・理由・実施者）を残す。

## 3. 定期確認（月次）
- 操作ログ・CSV 出力ログに不審な出力がないか（大量出力・深夜の出力）。
- 利用停止すべきユーザー（退職・異動）が残っていないか。
- 架電禁止の登録件数と解除理由。
- 「時間外の発信をブロック」が有効になっているか。
