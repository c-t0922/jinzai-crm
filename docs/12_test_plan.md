# 12. テスト計画

## 1. テストレベル

| レベル | ツール | 対象 | 実行タイミング |
|---|---|---|---|
| 単体 | Vitest | `server/domain`（発信前チェック、自動アクション、優先順位、KPI計算、正規化・重複判定） | PR毎（CI） |
| DB | pgTAP | 制約・ユニーク・RLS（ロール×テーブル×操作） | PR毎（CI） |
| 結合 | Vitest + ローカル Supabase | API（認可・冪等性・トランザクション） | PR毎 |
| E2E | Playwright | 業務シナリオ・画面操作・ショートカット | PR毎（主要）／夜間（全件） |
| 負荷 | k6 | 25万件・100万件での検索・一覧・架電API | Phase 1 完了前・Phase 2 同期後 |
| UI検証 | Playwright スクリーンショット＋目視 | PC 1920×1080 / **1366×768** / スマホ 390×844 | 画面実装毎 |
| セキュリティ | 権限違反テスト・依存脆弱性・シークレットスキャン | | PR毎＋リリース前 |

## 2. 業務シナリオ（完成基準・指示書21）

| # | シナリオ | 合格条件 |
|---|---|---|
| S1 | 管理者が架電可能な顧客からリストを作成 | 件数プレビューに架電禁止・許諾未確認が含まれない／除外内訳が表示される |
| S2 | 営業担当者へリストを割り当て | 均等割当で人数差 ±1 件以内、対応中顧客は割当対象外 |
| S3 | 担当者が架電センターで顧客を表示 | 優先順位どおりの顧客が表示、ロック取得 |
| S4 | 架電を開始 | モック発信で call_logs 作成、デモ表示、通話時間カウント |
| S5 | 架電結果を登録 | ワンクリック＋保存で1件のみ登録（二重登録なし） |
| S6 | 再架電またはアポを設定 | 不在→再架電キューに指定日時で出現／アポ獲得→アポイント一覧に自動登録 |
| S7 | 次の顧客へ進む | 次の顧客が自動表示、**自動発信されない** |
| S8 | 管理者ダッシュボードに実績反映 | 架電数・接続数・アポ数が 5 分以内（当日ライブ集計は即時）に反映、定義どおりの率 |
| S9 | 面談担当者へ引き継ぎ | CA のアポ詳細にヒアリング内容・顧客要約が表示、通知・タスクが作成 |
| S10 | 架電拒否した顧客が再度対象にならない | 同番号の別レコード含め、リスト・キュー・発信APIすべてで除外（API は 422） |

## 3. 異常系・非機能テスト

| 区分 | テストケース例 |
|---|---|
| 権限違反 | 架電担当が他人の割当顧客を API 直叩き → 404／RLS で 0 件／CSV出力 API → 403／EXE が個人情報を取得できない |
| 同時操作 | 2 名が同時に「次へ」→ 同一顧客が両者に出ない（並列 50 リクエストで検証）／同時に同一顧客へ発信 → 片方 409 |
| 通信切断 | 結果入力中にオフライン → 下書き保持 → 復帰後に自動再送、重複なし／通話中のブラウザリロード → 通話状態を復元 |
| 二重登録 | 保存ボタン連打・同じ Idempotency-Key 再送 → 1 件／Webhook 重複受信 → 1 回のみ処理 |
| 発信前チェック | 架電直前に許諾撤回・架電禁止登録 → 発信拒否／時間帯外 → 拒否 |
| 同期失敗（Phase 2） | kintone 500/429 → 指数バックオフでリトライ、途中再開（カーソル）、同期2回実行で重複なし、別人を自動統合しない |
| API制限 | 429 応答時にレート制御が働き、既存 kintone 業務に影響しない頻度に収まる |
| 大量データ検索 | 25万件：氏名部分一致・電話番号検索・複合条件 P95 < 2 秒／100万件で劣化確認 |
| 主要操作応答 | 結果保存・次へ・発信 API P95 < 1 秒（同時 50 ユーザー） |
| KPI | 分母0で「未計測」、架電数とユニーク顧客数の区別、コホート期間の混在なし |
| セキュリティ | 自動ログアウト、MFA 未設定の管理者がアクセス不可、ログに個人情報が出ない |
| 表示 | 1366×768 で架電センターの主要操作がスクロール不要、ローディング・空・エラー状態の表示 |

## 4. テストデータ
- `supabase/seed/generate.ts` で架空データを生成（氏名・電話は架空ルール：電話は `090-0000-xxxx` など実在しない番号帯【仮】）。
- 許諾状態の分布（granted 60% / unknown 35% / denied 5%）、架電禁止 1%、重複候補 2% を含める。
- 本番データのコピーは使用しない。

## 付録：KPI 計算式（単一定義）
| KPI | 式 |
|---|---|
| 架電数 | 期間内 `call_logs`（direction=out, status≠initiating失敗前）件数 |
| ユニーク架電顧客数 | `count(distinct contact_id)` |
| 接続数 | `call_results.is_connected = true` の件数 |
| 接続率 | 接続数 ÷ 架電数 |
| アポ獲得率（架電ベース／接続ベース） | アポ獲得数 ÷ 架電数 ／ アポ獲得数 ÷ 接続数 |
| 面談実施率 | 対象期間に**予定日がある**アポのうち実施数 ÷ 対象アポ数（キャンセル除外は設定で選択【仮】） |
| 入社率 | 対象期間に面談実施した人のうち入社人数 ÷ 対象面談者数（追跡期間は設定） |
| 1時間あたり架電数・アポ数 | 架電数 ÷ 稼働時間（初回発信〜最終発信、休憩除外は将来）【仮】 |
| 平均通話時間 | 接続通話の duration_sec 平均 |
| アポ獲得単価／成約単価 | （人件費＋通話料＋広告費【設定値】）÷ アポ数／成約数 |
| 売上目標達成率 | 確定売上 ÷ 目標 |
