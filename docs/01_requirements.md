## 1. 背景と目的

当社（不動産・住宅事業）は住宅系LP経由の顧客約25万件を kintone で管理している。新規事業の人材サービスのため、
**利用許諾を確認した既存顧客**と、将来の**人材LPからの新規反響**を一元管理する人材事業専用CRMを構築する。

目的（指示書 02）：既存データ活用／架電効率最大化／属人化解消／対応履歴一元化／KPIリアルタイム可視化／
アポ率・成約率向上／意思決定の高速化／人材LP連携／複数拠点への拡張。

## 2. スコープ

| フェーズ | 範囲 | 本番接続 |
|---|---|---|
| Phase 1 | 認証・権限、DB、ダッシュボード、顧客一覧/詳細、架電センター（モックCTI）、架電結果、架電リスト、アポイント、基本KPI、利用許諾・架電禁止管理 | なし（架空データ） |
| Phase 2 | kintone 連携（読み取り専用）、フィールドマッピング、大量同期、CTI 実通話、通話履歴、録音、詳細分析 | 少量の許諾済みデータで検証後、段階拡大 |
| Phase 3 | 求職者、キャリア面談、企業・求人、選考進捗、成約、売上・入金、経営分析 | |
| Phase 4 | 人材LP連携、新規反響自動割当、LINE等通知、AI文字起こし/要約/分析、広告ROI | |

**スコープ外**：既存 kintone への書き込み・削除、住宅ローン等の金融情報の利用、求職者向けマイページ（【要確認】）。

## 3. 利用者（ロール）

| ロール | 主な業務 | 想定人数【仮】 |
|---|---|---|
| システム管理者 | 全設定、連携、ユーザー管理 | 1〜2 |
| PM・事業責任者 | 全体分析、目標設定、リスト作成、割り当て | 1〜3 |
| チームリーダー | 所属チームの進捗・担当者管理 | 2〜5 |
| 架電担当者 | 割り当て顧客への架電、結果登録、アポ獲得 | 10〜30 |
| キャリアアドバイザー（CA） | 面談、求人紹介、選考管理 | 3〜10 |
| 経営陣 | 全体KPI・売上の閲覧 | 1〜5 |

同時利用は最大 50 名を初期想定【仮・要確認】。ユーザーは複数ロール兼務可（例：チームリーダー兼架電担当）。

## 4. 機能要件

### 4.1 共通
- F-COM-01 ログイン（メール＋パスワード）、管理者・PM は MFA 必須。
- F-COM-02 ロールに応じたサイドバーメニュー表示（指示書 04 のメニュー構成）。
- F-COM-03 自動ログアウト（2026-11-28 社長指示で既定は無効＝ログイン保持。「架電ルール設定」で分数を設定すると有効。通話中は操作扱い）。
- F-COM-04 操作ログ・ログイン履歴の記録。
- F-COM-05 スマートフォン：顧客情報・予定・KPI の閲覧に対応（架電操作は PC 前提）。

### 4.2 ダッシュボード（指示書 05）
- KPI 15 種（総顧客数〜売上目標達成率）、グラフ 10 種を表示。
- 絞り込み：期間／担当者／チーム／リスト／流入経路。前日・前週・前月比較。
- 架電担当者には自分の目標・進捗、PM には組織全体を表示（同一画面・表示内容をロールで切替）。
- KPIカードクリックで該当顧客一覧または詳細分析へ遷移（フィルタ条件を引き継ぐ）。
- Phase 1 で表示する KPI：架電・アポ系＋面談実施数まで。求人紹介〜売上は Phase 3 で実データ化（Phase 1 は「未計測」表示）。

### 4.3 架電センター（指示書 06）★最重要
- 3カラム構成（左：架電キュー／中央：顧客情報・架電操作／右：結果・次回アクション）。1366×768 に収める。
- 架電キューのタブ：本日の対象／再架電予定／新規反響／未対応／残件数表示。優先順位順。
- 架電結果ステータス 16 種（指示書 06）。結果ごとに「表示する入力欄」「自動アクション」をマスタで定義（`04_business_flow.md` 表）。
- 自動アクション例：不在→再架電候補（N時間後【仮：翌営業日同時間帯】）、アポ獲得→アポイント自動登録、架電拒否→即時架電禁止登録。
- 操作性：ワンクリック発信、結果ワンクリック登録、保存後に次顧客を自動表示（自動発信はしない）、ショートカット、
  二重発信防止、同一顧客の同時架電防止（ロック）、入力途中の自動保存（下書き）、通信エラー時の再送キュー。
- 発信直前にサーバーで「利用許諾=許諾済」「架電禁止でない」「ロック取得済」「架電可能時間帯内」を確認。
- 架電可能時間帯【仮：平日・土曜 10:00〜20:00、日祝不可】は架電ルール設定で変更可能。

### 4.4 CTI（指示書 07）
- CTI は `CtiProvider` インターフェースで抽象化。Phase 1 はモックプロバイダ（画面に「デモ通話」バッジを常時表示）。
- 機能：ブラウザ発信、着信時顧客表示、通話開始/終了時刻・通話時間自動記録、発着信履歴、通話ステータスのリアルタイム反映、
  マイク/ヘッドセット確認、失敗時エラー表示、録音（デフォルト無効）、録音再生、担当者別通話実績。
- 将来：AI 文字起こし・要約・項目抽出・トーク分析（担当者が確認・修正できる）。

### 4.5 kintone 連携（指示書 08）
- 読み取り専用。APIトークンはサーバー側（暗号化保存または環境変数）でのみ管理。
- フィールドマッピング画面、初回一括同期（カーソルAPI）、更新日時による差分同期、定期自動同期、手動同期、
  同期履歴・エラー・リトライ・進捗表示。
- データ品質：電話番号の E.164 正規化、メール正規化（小文字化・前後空白除去）、重複候補検出（自動統合しない）、
  電話欠損の分類、無効データ除外、取得元・kintoneレコードIDの記録、利用許諾状況の確認。
- 同期の冪等性：`(source_system, source_app_id, source_record_id)` のユニーク制約で upsert。
- 利用許諾不明の顧客は「架電不可」で取り込む。

### 4.6 架電リスト管理（指示書 09）
- 条件ビルダー（AND/OR のネスト可）。条件項目は指示書 09 の11項目。禁止項目（金融情報）は選択肢に出さない。
- 抽出件数の事前確認、保存、名称、チーム割当、担当者均等割当、優先順位、一時停止、リスト別分析、動的リスト（定期再評価）。
- 自動割当の優先順位（初期値・管理画面で変更可）：①本日再架電予定 ②人材LP新規反響 ③転職相談希望 ④未架電の許諾済 ⑤再架電可能な不在。
- 割当対象外：架電禁止／利用許諾未確認／他担当者が対応中（ロック中）。

### 4.7 顧客一覧・詳細（指示書 10）
- 氏名・電話・メール検索、詳細絞り込み、ソート、表示列変更、保存済み検索、担当者変更、タグ、一括操作、権限付きCSV出力。
- サーバーサイドページネーション。25万件で一覧表示 2 秒以内。
- 詳細：基本情報／流入情報／利用許諾履歴／架電履歴／録音／メモ／アポ履歴／担当者変更履歴／タスク／面談・選考・成約履歴をタイムライン表示。

### 4.8 アポイント・タスク（指示書 11）
- アポ登録、担当割当、CAへの引き継ぎ（顧客情報＋ヒアリング内容を自動添付）、形式（オンライン/電話/対面）、URL、
  リマインダー、日程変更、キャンセル、実施/未実施記録、カレンダー表示、本日のタスク、期限切れ通知。
- 将来：Google カレンダー連携。

### 4.9 人材事業進捗（指示書 12・Phase 3）
- 本人の意思確認後に求職者登録。ステータス 14 種（初期値・マスタで変更可）。カンバン／一覧切替。
- ステータス変更日時・変更者を履歴テーブルに記録し、滞留期間・歩留まりを分析。
- 企業・求人・紹介手数料・返金規定・入金予定日を管理できる構造を Phase 1 の DB 設計時点で用意。

### 4.10 KPI・分析（指示書 13）
- KPI 定義は `docs/12_test_plan.md` 付録の計算式に準拠（指示書 13 の定義をそのまま採用）。
- 架電件数（`call_logs` 件数）とユニーク顧客数（`count(distinct contact_id)`）を区別。
- 面談実施率・入社率は **コホート方式**（対象期間に獲得したアポ／実施した面談を母集団とし、その後の結果を追跡）で統一。
- 分析軸：日・曜日・時間帯・担当者・チーム・リスト・流入経路・問い合わせ時期・トークスクリプト。
- データ無し・分母0は「未計測」。

### 4.11 管理者設定
ユーザー、チーム、KPI目標、kintone連携、LP連携、CTI連携、トークスクリプト、架電ルール、個人情報・利用許諾、操作ログ。

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 通常画面表示 2 秒以内、主要操作応答 1 秒以内（P95）。25万件で負荷試験、100万件まで線形劣化しない設計 |
| 拡張性 | 通話ログ・操作ログが数百万〜数千万件。月次パーティション（`call_logs`, `audit_logs`） |
| 可用性 | Vercel + Supabase のマネージド SLA に準拠。営業時間内の計画停止なし |
| セキュリティ | `15` 章の全項目（`06_permission_matrix.md` と `02_system_architecture.md` §セキュリティ参照） |
| バックアップ | Supabase 日次バックアップ＋PITR（Proプラン以上）。復元手順書を Phase 1 完了時に作成・リハーサル |
| データ保管 | 保管期限は設定可能【要確認】。期限到来データは匿名化または削除ジョブで処理 |
| 監査 | 操作ログ・出力ログ・ログイン履歴を最低 1 年保持【仮】 |
| アクセシビリティ | キーボード操作、フォーカス表示、コントラスト比 4.5:1 以上 |
| 対応ブラウザ | PC：Chrome/Edge 最新（架電は Chrome 推奨）。スマホ：iOS Safari / Android Chrome 最新 |

## 6. 前提・制約
- 開発環境は架空データのみ。本番個人情報は開発・AI に一切渡さない。
- 既存 kintone に影響を与えない（読み取り専用、APIレート制限遵守、業務時間外に大量同期）。
- 利用許諾の判断基準は社内（法務・個人情報管理責任者）が決定する【要確認】。システムは判断結果を記録・反映する。
