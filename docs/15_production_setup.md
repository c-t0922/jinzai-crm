# 15. 本番環境の構成と運用開始手順

版：2026-11-28（架電開始目標 2026-11-30）。費用は無料プランのみ。

## 1. 構成

| 項目 | 内容 |
|---|---|
| アプリ | Netlify（Free）プロジェクト `iegao-jinzai-crm` → https://iegao-jinzai-crm.netlify.app 。`main` への反映で自動公開 |
| DB・認証 | Supabase（Free）プロジェクト `jinzai-crm`（東京 ap-northeast-1）。GitHub 連携で `main` へのマージ時に `supabase/migrations` を自動適用 |
| 発信 | 手持ちの電話（`CTI_MODE=manual`、本番の既定値）。Twilio は後日 |
| 環境変数（Netlify） | `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`（秘密。社長が直接入力、リポジトリ・チャットに残さない） |
| 認証設定（Supabase） | 新規登録オフ、Site URL = 本番 URL、Redirect URLs = `https://iegao-jinzai-crm.netlify.app/**` |

### 無料プランの制約

- DB 容量 500MB。顧客 25 万件で約 330MB の見込み。架電履歴が増えたら Pro（月 25 ドル）を検討
- 7 日間アクセスが無いと一時停止（ダッシュボードから再開可）
- 自動バックアップなし（顧客は kintone から再取り込みで復元可。架電履歴は失われうる）
- 標準メールは Supabase 組織のメンバー以外に届かず、テンプレート変更不可 → 招待・パスワード設定はリンク発行方式

## 2. 最初の管理者（社長）

1. Supabase → Authentication → Users → 「Add user」→「Create new user」で本人のメールアドレスを登録（パスワードは本人が後で設定）
2. SQL エディタで `select bootstrap_first_admin('メールアドレス', '氏名');`（管理者が 1 人もいない時だけ動く）
3. 本番 URL の「パスワードを忘れた方」から再設定メールを送り、リンクからパスワードを設定（Supabase 組織のメンバーには届く）
4. 初回ログイン時に多要素認証（認証アプリ）を登録

## 3. 架電担当者の追加

管理者設定 →「ユーザー管理」→「ユーザーを招待」→ 発行された招待リンクを本人へ直接送る（LINE 等）。本人がリンクを開いてパスワードを設定する。忘れた場合は同じ画面の「パスワード設定リンクを発行」。

## 4. 顧客データの投入

1. kintone で顧客アプリを CSV 出力（文字コードはどちらでも可）。**住宅ローン審査・借入・資産・年収の列は出力しない**（含まれていても取り込み画面で除外される）
2. 管理者設定 →「顧客CSV取り込み」でファイルを選び、項目を対応付けて取り込む（25 万件で 10 分前後。途中で止まっても同じファイルで再実行すれば続きから反映）
3. 取り込んだ顧客は全員「利用許諾：未確認＝架電不可」。架電可能にするには、許諾の根拠を確認したうえで
   - CSV の許諾列を対応付けて根拠を記入して取り込む、または
   - 「個人情報・利用許諾管理」の一括登録（根拠必須・監査ログ記録）

## 5. 架電

架電センター →「発信」で番号が表示される（スマホならタップで発信）。通話の結果に応じて「つながった／不在／話し中」→ 終話 → 架電結果を選んで保存。次の顧客は自動表示されるが、発信は必ず人が操作する。

架電可能時間は月〜金 10:00〜20:00（管理画面「架電ルール設定」で変更可）。

## 6. 変更の反映

`main` にマージすると、Supabase がマイグレーションを適用し、Netlify が再ビルドして公開する。
